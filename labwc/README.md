# labwc

Our patches on top of Labwc releases, one file per patch, each with a DEP-3 header saying why
(the scheme of grigio/labwc-blur). Debian's `labwc` package is rebuilt with them by
`packages/build.sh labwc` (`packages/labwc/` lists them in `series`).

| Patch | What |
|---|---|
| `0001-scenefx-scene-header.patch` | every file that uses the scene graph includes the SceneFX header instead of the wlroots one; mechanical, generated by `tools/scenefx-includes.sh` |
| `0002-scenefx-renderer.patch` | link against `libscenefx-0.5` (ahead of wlroots) and render with the SceneFX renderer; handle the node types SceneFX adds |
| `0003-scenefx-rounded-corners-and-shadows.patch` | round all four window corners and draw soft shadows with SceneFX, for server-side and client-side decorated windows and in window captures; new theme keys `window.{active,inactive}.shadow.offset.{x,y}` |
| `0004-per-output-and-dynamic-workspaces.patch` | `<desktops perOutput="yes">`: every output has workspaces of its own; `<desktops dynamic="yes">`: the user adds and removes workspaces, as on macOS |

Upstream Labwc declined SceneFX (labwc/labwc pull request 3751), so the stack is carried here.

**Rounded corners and shadows (0003).** `<theme><cornerRadius>` now rounds all four corners: the
outside of server-side decorations, the window content inside the border, windows with client-side
decorations and window captures (`grim -T`). `<theme><dropShadows>` draws a SceneFX shadow behind
every window, sized by `window.*.shadow.size` and moved by `window.*.shadow.offset.x/y`. Labwc's
defaults are kept (radius 8, no shadows); Dodo's look comes from `dodo-theme` and the session config.
Corners are square and shadows off for maximized and fullscreen windows; tiled windows are square
and get shadows only with `dropShadowsOnTiled`. Clients that draw their own frame and shadow (GTK4)
are left alone. Known limits: single-pixel buffers (some video players) stay square, the shadow
blur does not grow with the output scale, Alt-Tab thumbnails are square, and a shaded window keeps a
square titlebar bottom. On a plain white background a faint edge of the shadow can show where
SceneFX's shader stops, at twice the Gaussian's standard deviation.

**Workspaces per output (0004).** Two options, both off by default. With `perOutput` every output
has its own workspaces and its own workspace group in ext-workspace-v1, so a panel shows the
workspaces of its monitor. `GoToDesktop` switches the output nearest to the cursor, `SendToDesktop`
counts from the window's workspace, and a window moved to another output goes to that output's
current workspace. When an output leaves the layout its windows move to another output, to the
workspace with the same position. With `dynamic` the user adds and removes workspaces, as on macOS:
`AddDesktop` and `RemoveDesktop`, `GoToDesktop`/`SendToDesktop` to the right of an occupied last
workspace, or a panel's "+" and "x" through ext-workspace-v1. Empty workspaces stay, workspaces do
not wrap, and they are named by position. Changing either option needs a restart. Asked for upstream in labwc/labwc issue 932.

**GLES2 is required.** The SceneFX renderer is GLES2 only: a patched Labwc does not start with the
pixman renderer. Software GLES2 (Mesa llvmpipe) works, which is how `packages/labwc/test.sh`
starts it headless.

## A new Labwc release

1. Check out the release in a clean git tree and regenerate the mechanical patch:
   `labwc/tools/scenefx-includes.sh <tree> > labwc/patches/0001-scenefx-scene-header.patch`.
2. `packages/build.sh labwc`. Patches are applied without fuzz, so one that no longer fits fails the
   build instead of landing in the wrong place; refresh it on top of the new release.

**llvmpipe on amd64.** Headless on Mesa llvmpipe, Labwc crashed on amd64 (arm64 drew). The cause
is not SceneFX: wlroots' udmabuf allocator gives the 10x16 hardware cursor buffer a stride of
40 bytes, and llvmpipe on x86 reads colour rows with aligned 16-byte loads. The package test
therefore runs Labwc with a software cursor (see `packages/labwc/test.sh`). `tools/llvmpipe-probe/`
draws SceneFX's operations, the cursor buffer and plain GLES2 cases one at a time on llvmpipe and
reports which ones crash: run `tools/llvmpipe-probe/run.sh` locally or the `llvmpipe-probe`
workflow (by hand, in the Actions tab).

**llvmpipe and window captures.** A window capture renders into a udmabuf buffer of exactly the
window's size. llvmpipe writes render targets in 4x4 tiles and runs past the end of that buffer when
its height is not a multiple of 4; Labwc crashes when the overrun crosses into an unmapped page,
so at random (stock Labwc too, amd64 and arm64). The package test therefore sizes its windows so
that their captures are multiples of 4. Hardware GPUs are not affected.
